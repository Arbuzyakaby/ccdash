# ccdash — дашборд расхода токенов Claude Code

Локальный, офлайновый, без зависимостей. Считает статистику по транскриптам
сессий Claude Code и складывает её в один HTML-файл.

**Живая версия: https://arbuzyakaby.github.io/ccdash/**

## Запуск

```
python collect.py
```

Одна команда делает всё: читает транскрипты, пересобирает `usage.db`, сверяется
с `ccusage` и заново собирает `index.html`. Дальше `index.html` открывается
двойным кликом — это самодостаточная страница, ничего никуда не ходит.

Флаги: `--no-html` (только база), `--no-crosscheck` (не звать ccusage),
`--projects DIR`, `--db PATH`, `--html PATH`.
Отдельно пересобрать только страницу из готовой базы: `python render.py`.

## Файлы

| Файл | Что это |
|---|---|
| `collect.py` | парсер транскриптов → SQLite, сверка с ccusage, запуск сборки страницы |
| `render.py` | сборка `index.html` из `usage.db` |
| `theme.css` | тема: токены, палитра, типографика, плотность — инлайнится при сборке |
| `pricing.json` | тарифы моделей, $/1M токенов |
| `usage.db` | агрегаты: таблица `calls` (строка = один вызов к API), `meta`, вьюхи |
| `index.html` | сам дашборд |

`usage.db` в репозиторий не попадает — это промежуточные агрегаты, странице они
не нужны. `index.html` коммитится: из него собирается страница на GitHub Pages.

## Публикация

Страница раздаётся GitHub Pages из корня ветки `main`. Чтобы обновить и её тоже:

```
python collect.py
git commit -am "обновление данных" && git push
```

Через минуту-две новая версия на https://arbuzyakaby.github.io/ccdash/.

**Опубликованная страница видна всему интернету.** В ней ваши реальные цифры:
названия проектов, идентификаторы сессий, почасовая активность и объёмы работы.
Это осознанный выбор владельца репозитория. Если понадобится закрыть:

```
gh api -X DELETE repos/<владелец>/ccdash/pages   # снять сайт
gh repo edit <владелец>/ccdash --visibility private --accept-visibility-change-consequences
```

Форкнули к себе и не хотите публиковать свою статистику — верните `index.html`
в `.gitignore` и не включайте Pages. Инструмент от этого работать не перестанет:
он и задуман как локальный.

## Оформление

Визуальное направление — стиль Data-Dense Dashboard, пара Fira Sans / Fira Code,
синяя палитра с янтарным акцентом, плотность 8/10. Шрифты подключены локальным
стеком без обращения к Google Fonts: страница обязана открываться офлайн, а без
установленной Fira стек падает на системный шрифт.

Цвета серий на графиках живут по отдельным правилам и заданы не темой оформления,
а палитрой, проверенной на дальтонизм и контраст в обоих режимах: типы токенов —
blue / aqua / orange / violet, модели — green / magenta. Менять их «под настроение»
нельзя, только вместе с повторной проверкой.

## Приватность

В транскриптах Claude Code лежат полные тексты диалогов и кода. Парсер читает
из каждой записи **только** это:

```
message.id, requestId, sessionId, timestamp, cwd, gitBranch, version,
effort, isSidechain, message.model, message.usage.*
```

Поля `message.content`, `toolUseResult`, `lastPrompt`, `customTitle`, `aiTitle`,
`summary`, `attachment` не читаются вовсе. Ни сборщик, ни страница не делают
сетевых запросов. Проверить можно так:

```
python -c "print(any(n in open('usage.db','rb').read() for n in (b'\"role\"', b'\"content\"', b'import ', b'def ')))"
```

## Как считаются цифры

**Дедуп обязателен.** Один и тот же вызов к API попадает в транскрипты по
нескольку раз — при resume, rewind и в файлы сабагентов. На текущих данных это
**половина всех записей**. Ключ дедупа — пара `message.id + requestId`.

**Оборванные снимки.** Изредка копии одного ключа расходятся по
`output_tokens`: сначала пишется оборванный снимок стрима (2–8 токенов), потом
финальная запись. Берётся самая полная копия, иначе итог по output занижается.

**Вложенные файлы.** Транскрипты сабагентов лежат в
`<проект>/<sessionId>/subagents/agent-*.jsonl`. Плоский glob их теряет — обход
рекурсивный.

**Имена проектов.** Папки в `~/.claude/projects/` содержат искажённый путь
(кириллица схлопнута в дефисы), поэтому имя берётся из поля `cwd`. Подкаталоги
схлопываются в родительский проект по папке, которую завёл сам Claude Code.

**Кэш.** Запись кэша тарифицируется по времени жизни: 1 час — 2× от базового
input, 5 минут — 1.25×. В наблюдаемых данных весь кэш часовой. Считаются обе
суммы, `cost_1h` и `cost_5m`; разница показана на дашборде отдельно.

**Сверка.** На каждом прогоне итоги сравниваются с независимой утилитой
`ccusage claude daily --json --offline`. Сейчас сходятся до цента по input,
output, записи кэша, чтению кэша и стоимости.

## Деньги

Дашборд показывает, **во сколько обошёлся бы тот же расход по тарифам Anthropic
API**. Это не счёт: подписка Claude Pro оплачивается фиксированно и от этих
цифр не зависит. Данных о фактическом биллинге в системе нет и взять их
неоткуда — Anthropic Console учитывает только потребление по API-ключам.

## Хрупкость формата

Формат транскриптов Claude Code недокументирован и меняется между версиями CLI.
Парсер написан защитно: отсутствующие или неожиданные поля не роняют прогон, а
попадают в счётчики. Раздел «САНИТАРНЫЕ ПРОВЕРКИ ФОРМАТА» в выводе `collect.py`
и блок в подвале дашборда показывают эти счётчики. Если после обновления CLI
там появятся ненулевые значения — особенно «новых полей в usage» или «моделей
без цены» — цифрам верить нельзя, парсер надо чинить.

Новую модель достаточно добавить в `pricing.json`: до этого её вызовы считаются
в токенах, но со стоимостью 0, и она попадает в предупреждение.
